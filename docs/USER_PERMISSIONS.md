# 账号与菜单权限

账户用于登录，姓名用于右上角显示。菜单授权同时决定页面可见性和页面操作权限；后端按相同权限限制接口，旧 role_codes 不授予这些接口访问权。

## 权限规则

- `ALL_BUSINESS`：自动包含菜单目录中的当前与未来业务菜单；用户管理独立授权。
- `CUSTOM`：仅包含 `sys_user_menu_permission` 中已授权且仍存在于目录的菜单；新增菜单默认不授权。
- `owner=true`：老板账号始终拥有全部权限，不能停用或删除，仅本人可编辑姓名、账户、密码。
- `users`：用户管理权限，可以管理其他普通账号，包括授予业务权限和用户管理权限。
- 删除用户为软删除，停用、删除、改账户及重设密码会使该用户已有会话失效。自己修改密码会撤销全部会话；退出登录仅撤销当前会话。
- 无业务或管理菜单权限的账号进入“暂无功能权限”，仍可修改密码、退出登录。

## 增加未来菜单

在 `MenuCatalog` 注册稳定编码、分类、中文名称、路径及 business 标记，并增加对应前端路由和后端接口授权映射（`MenuPermissionService` 与控制器方法权限）。侧边栏与权限树从后端目录生成，无需再维护一份固定角色列表。业务菜单使用 `business=true`；管理菜单使用 `false` 并单独授权。

引用资料通过只读 `/references/customers`、`/references/products` 提供给已授权流程，不授予基础资料 CRUD。跨页面共享操作需在后端按其实际所属流程明确授权；打印、搜索及附件同时校验权限。

## 接口

- `/auth/login`、`/auth/me` 返回安全 user、menuCatalog、fieldPermissions；登录另外返回 token。user 包含 id、username、realName、enabled、owner、permissionMode、menuCodes、effectiveMenuCodes，无密码哈希。
- `/system/users` 的新增/编辑请求包含 username、realName、password、enabled、permissionMode、menuCodes。编辑密码留空保持原密码。
- `/auth/change-password` 要求 oldPassword、newPassword、confirmPassword。
- `/auth/logout` 撤销当前登录会话。令牌使用用户 ID 与服务端会话 ID，过期或撤销返回 401，缺少菜单授权返回 403。
- 前端路由切换、窗口聚焦及每30秒刷新账户权限；切换账号时清除缓存。

## 原料出入库员工权限（2026-10-20）

在用户管理新增员工，填写真实姓名、登录账户和密码，在“库存操作 → 原料出入库登记”下分别勾选“出库登记”（material-entry-out）和“入库登记”（material-entry-in）并启用。可以只选一项，也可以两项都选。员工可独立登录扫码或网页选料登记，不需要开放“原料库存”，也不能查看其他业务或管理用户。ALL_BUSINESS和老板自动包含两项权限。原来的合并权限 material-entry 兼容为两项，读取不改写数据库；管理员编辑保存后存储独立权限。

员工扫码后在手机页登录，登录后继续当前原料的登记；有有效会话时显示当前员工姓名和账户。从“库存操作 → 原料出入库登记”菜单或只有此权限的账号登录系统后，进入原料选择页：电脑每行五个原料气泡，手机自动排布，可以上下滚动、搜索原料，点击直接登记，沿用当前账号，无需扫码或再次登录。停用和资料待完善的原料不可选。登记页只显示账号获准的操作；只有一项权限时自动选中对应类型。后端对原料列表、信息查询和登记均验证登录与权限，每次请求加载最新账号状态，并独立校验入库/出库方向；撤销权限、停用或删除账号后阻止继续登记。

每笔流水保存操作人姓名、登录账户和用户编号快照，禁止客户端指定操作人。每日记录为一天的汇总，“最后操作人”仅表示最后更新人；逐笔责任查看“数量流水”。旧匿名历史保持原样，不猜测补写员工。二维码仍固定不变。
